📦 Pilihan CDN untuk Assets

Dokumentasi lengkap tentang Content Delivery Network (CDN) yang tersedia untuk project Komando Apps, termasuk informasi dukungan Content Security Policy (CSP). Repository sumber: KomandoLand/assets.

1. jsDelivr ✓ CSP SUPPORT

Status: MENDUKUNG Content Security Policy

Rekomendasi: Primary CDN untuk production

Keunggulan:

  • Kompatibel penuh dengan strict CSP headers
  • Sistem cache optimal dengan versioning
  • Fallback otomatis ke multiple mirrors
  • CORS headers yang tepat
  • Support Subresource Integrity (SRI)

URL Pattern:

https://cdn.jsdelivr.net/gh/KomandoLand/assets@1.0.0/vendors/jquery/jquery.min.js?r=1782870997

Contoh CSP Header:

Content-Security-Policy: script-src 'self' https://cdn.jsdelivr.net

2. GitHub Pages ✗ NOT SUPPORT CSP

Status: TIDAK mendukung Content Security Policy

Rekomendasi: Development/testing only

Keterbatasan:

  • Akan di-block oleh strict CSP policies
  • Tidak ada integrity hash support
  • CORS headers terbatas
  • Tidak cocok untuk production dengan security ketat

URL Pattern:

https://komandoland.github.io/assets/vendors/jquery/jquery.min.js

Use Case: Development lokal, testing tanpa CSP, prototyping

3. StaticDelivr ✓ CSP SUPPORT

Status: MENDUKUNG Content Security Policy

Rekomendasi: Production alternative dengan CSP support

Keunggulan:

  • CSP Compatible - dapat di-whitelist dalam CSP policies
  • Multi-CDN Architecture - beberapa CDN untuk availability tinggi
  • Consistent Domain - semua aset melalui domain yang sama
  • WordPress Integration - plugin otomatis untuk rewrite URL aset
  • Auto Fallback System - fallback otomatis ke server asal jika gagal

URL Pattern:

https://cdn.staticdelivr.com/gh/KomandoLand/assets/1.0.0/vendors/jquery/jquery.min.js

Use Case: Production alternative dengan CSP support dan fallback capability

Contoh CSP Header:

Content-Security-Policy: script-src 'self' https://cdn.staticdelivr.com
💡 Rekomendasi Implementasi:
  • Production Environment: Gunakan jsDelivr sebagai primary CDN. Pastikan CSP headers di-set dengan benar di server.
  • Development Environment: Bisa menggunakan GitHub Pages untuk kemudahan testing tanpa CSP.
  • Production Alternative: Gunakan StaticDelivr jika membutuhkan Multi-CDN Architecture, WordPress Integration, atau Auto Fallback System.
  • Staging Environment: Gunakan jsDelivr untuk simulasi kondisi production yang akurat.

⚙️ Contoh Implementasi

Cara 1: Pilih CDN Sesuai Environment (Recommended)

<!-- Production: CSP-Compatible --> <script src="https://cdn.jsdelivr.net/gh/KomandoLand/assets@1.0.0/vendors/jquery/jquery.min.js?r=1782870997"></script> <!-- Development: Non-CSP --> <!-- <script src="https://komandoland.github.io/assets/vendors/jquery/jquery.min.js"></script> -->

Cara 2: Fallback Chain

<script src="https://cdn.jsdelivr.net/gh/KomandoLand/assets@1.0.0/vendors/jquery/jquery.min.js?r=1782870997"></script> <script> // Fallback jika primary CDN gagal if (typeof jQuery === 'undefined') { document.write('<script src="https://komandoland.github.io/assets/vendors/jquery/jquery.min.js"><\/script>'); } </script>

Cara 3: Integrasi Komando Apps (CodeIgniter)

app/Views/themes/modern/header.php memuat assets dari CDN hanya ketika ENVIRONMENT !== 'development', memakai pola raw.githack dengan commit SHA yang di-pin:

<link rel="stylesheet" href="https://rawcdn.githack.com/<owner>/assets/<commit-sha>/themes/modern/builtin/css/site.css?r=<?=time()?>"/>
⚠️ Perhatian: karena SHA di-pin, perubahan yang sudah di-push ke repository belum otomatis tayang. Update SHA di header.php setelah push, atau migrasikan ke jsDelivr dengan tag versi agar cukup menaikkan nomor versi saja.

📝 Notes

  • Version saat ini: 1.0.0
  • jsDelivr dan StaticDelivr membaca versi dari git tag — buat tag dulu dengan git tag -a 1.0.0 -m "..." && git push origin 1.0.0
  • GitHub Pages perlu diaktifkan di Settings → Pages (branch main, root) agar URL komandoland.github.io aktif
  • Parameter ?r=1782870997 pada jsDelivr adalah cache buster untuk force refresh
  • Selalu test CSP compatibility di staging sebelum deploy ke production
  • Perubahan pada themes/ harus sejalan dengan folder public/ di repository komando-apps
